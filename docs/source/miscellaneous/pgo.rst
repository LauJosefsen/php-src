#############################
 Profile-guided optimization
#############################

Profile-guided optimization (PGO) uses measurements from an instrumented PHP build to optimize a
second build. The ``prof-gen`` and ``prof-use`` make targets support GCC and Clang. These targets
are optional; a normal ``make`` does not enable PGO.

Use the same source tree, compiler, architecture, configure options and optimization flags for
both phases. Keep the build directory in place while collecting profiles and rebuilding. GCC
records counters beside the object files; Clang records raw profiles in ``pgo-data/`` under the
build directory.

**************************
 Build, train and rebuild
**************************

Configure PHP with the features required by the training applications. For example:

.. code:: shell

   ./buildconf --force
   ./configure --enable-zts --enable-embed
   make -j8 prof-gen

``prof-gen`` removes old objects and profiles, builds an instrumented interpreter with atomic
counter updates, then removes profiles produced by build-time tools. Run the instrumented PHP
binary or embedded library against the training applications before rebuilding:

.. code:: shell

   sapi/cli/php -d opcache.jit=disable -d opcache.jit_buffer_size=0 training.php
   make -j8 prof-use

``prof-use`` checks for training profiles before removing the instrumented objects. It then
builds an optimized interpreter without instrumentation. Training applications and configurations
must also keep JIT disabled when comparing interpreter build optimizations.

For Clang, configure with the chosen compiler and select the corresponding ``llvm-profdata``
executable if it is not named ``llvm-profdata``:

.. code:: shell

   CC=clang ./configure --enable-zts --enable-embed
   make -j8 prof-gen
   sapi/cli/php -d opcache.jit=disable -d opcache.jit_buffer_size=0 training.php
   make -j8 prof-use LLVM_PROFDATA=llvm-profdata

``prof-use`` automatically merges the raw Clang profiles into ``pgo-data/php.profdata``. To merge
and inspect them before rebuilding:

.. code:: shell

   make prof-merge LLVM_PROFDATA=llvm-profdata
   llvm-profdata show --all-functions --counts pgo-data/php.profdata

``make prof-clean`` removes compiled objects and binaries while preserving training data.
``make prof-reset`` removes GCC counters, raw Clang profiles and the merged Clang profile while
preserving compiled objects. ``make prof-gen`` starts a new training cycle and discards the
previous cycle's profiles.

The make variables ``PROF_GEN_FLAGS`` and ``PROF_USE_FLAGS`` allow custom compiler profiling
flags. Retain ``-DPHP_PGO_GENERATE`` in generation flags to flush profiles at PHP module shutdown,
and ``-DPHP_PGO_USE`` in use flags to keep the shutdown path excluded from profiling in both phases.
``PGO_DATA_DIR`` controls the Clang profile directory; use the same value for generation,
training, merging and profile use. If ``LLVM_PROFILE_FILE`` is set during Clang training, keep its
output in that directory so that ``prof-merge`` can discover the profiles.

*************************
 Representative training
*************************

Training should cover the work performed by the applications that will use the optimized build.
Include application startup, persistent workers, fresh application instances, CLI jobs,
validation, serialization, template rendering, container resolution and instrumentation as
appropriate. Exercise successful and failing inputs, common and infrequent branches, and the
native extensions required by the applications. Train each SAPI that will be deployed.

Choose the relative frequency of these operations to reflect the expected application mix.
Separate training inputs from evaluation inputs, and include workloads absent from training to
check whether the gains generalize. A small smoke test checks the build machinery; it is not a
representative performance training workload.

Inspect profile coverage and compiler diagnostics. A profile generated by a different source
revision or compiler can be incompatible even when its files exist. Regenerate profiles when
changing PHP, the compiler, architecture, extensions, configure options or optimization flags.

****************
 Embedded hosts
****************

Instrumented builds flush counters during ``php_module_shutdown()``. An embedded host must call
PHP's shutdown routines after training and before terminating. This also writes profiles when
the host exits without invoking the C runtime's exit handlers. Atomic counters support training
with multiple PHP threads; the host must stop those threads before shutting down PHP.

Only instrumented builds contain this flushing hook. The optimized build does not add a
userland function, and the hook is absent from normal builds.

***************************
 Build workflow smoke test
***************************

The Linux shared-embed smoke test verifies that an untrained ``prof-use`` fails without replacing
the current interpreter, that the generation and use phases rebuild objects, and that an
embedded process writes profiles before calling ``_Exit()``. It also checks identical output and
the absence of new profiles after an optimized run.

From a fresh build configured with ``--enable-embed`` and with ``make`` completed:

.. code:: shell

   MAKEFLAGS=-j8 sh /path/to/php-src/build/tests/pgo.sh /path/to/php-src

For Clang, set ``LLVM_PROFDATA`` to the matching executable if necessary. The test replaces the
current build with an instrumented build and then a profile-use build, and clears profiling data.
